Many synthetic-biology biosensors report a signal molecule by expressing a fluorescent protein. Ours reports the quorum-sensing molecule AHL. Turning that fluorescence into a number you can trust takes more than reading a value: backgrounds must be subtracted, replicates combined, a standard curve fitted, and its limits respected.

LasReader packages those steps into web tools that open in a browser with nothing to install. It serves the plate reader and our own instrument, CAPTURE-Screen, through one shared calibration model.

  • Source code on iGEM GitLab
  • Open the live app
  • MIT License
Research use only. LasReader reports relative fluorescence and AHL concentrations inferred from a calibration curve. It is not intended for diagnostic use.

What it is for

Three commitments run through every page of the tool. Each card turns over to show how it is kept.

Nothing to install
The frontend is a plain static site with no build step. A wet-lab member uploads a file or follows the numbered steps at the instrument; no programming is needed.
Every number has an interval
A concentration is never shown alone. It carries a 95% confidence interval that combines the noise of the reading with the uncertainty of the fitted curve.
It never extrapolates
Outside a curve's usable range the software says "below LOD" or "above range" and gives no number. Everything shown is a real reading: there is no simulated device or demo data in the tool.

Who it is for

  • Wet-lab members of iGEM teams and other labs who characterize a fluorescent biosensor, especially one that responds to AHL.
  • Teams building a low-cost fluorescence reader. CAPTURE-Screen's firmware, its data model and its calibration workflow can be reused with any AS7341-based device.
  • Developers extending the tools. Each analysis step is a separate module, and the backend exposes a documented REST API.

Three tools, one model

Tool 1

Plate Reader Assay

AHL standards and samples read together on any plate reader, fitted into a standard curve, with each sample's inferred AHL and its 95% CI.

  1. Enter data. One row per standard (0 nM for blanks) or sample, up to six replicates. Type, paste from Excel, or paste the 8 × 12 plate and mark the wells on a plate map. Optionally normalize to cell density (F ÷ OD600).
  2. Fit. Review the standards, exclude a reading only with a reason, and fit the 4PL. At least 4 non-zero concentrations and 2 blanks are required.
  3. Results. Each sample's replicates are averaged and converted once: AHL in the well with a 95% CI, and in the original sample (× dilution).
  4. Export. A CSV with every reading, the curve and each result, plus the curve as a PNG. Nothing is stored.
Tool 2

Cross-Validation

The same samples inferred on a plate reader and on CAPTURE-Screen, paired by name: the evidence that our reader agrees with a commercial one.

  1. Plate reader. Load the CSV exported by the Plate Reader Assay.
  2. CAPTURE-Screen. Choose a measurement batch kept in the browser, or load its CSV, with its dilution.
  3. Comparison. A table, a log-log plot against y = x, the geometric mean ratio, Bland–Altman 95% limits of agreement, and how many 95% CIs overlap.
  4. Export. The comparison as CSV, the plot as PNG.
Tool 3

CAPTURE-Screen interface

The control software for our fluorescence reader (ESP32 + AS7341). A step bar on every page shows which step comes next.

  1. Instrument. Check that backend, device, sensor and LED are connected, then run a buffer-only self-check of dark stability and saturation.
  2. Calibrate. Enter the strain and standards, read each tube in the order shown (or enter recorded values), fit the 4PL and save the curve.
  3. Curves. Review each saved curve: its fit, LOD/LOQ, usable range, and whether it matches the instrument now.
  4. Measure. Choose a curve, read the blanks, read each sample in replicate tubes, and export the batch.

A separate Data page backs up, restores or deletes all runs, curves and batches. The landing page also shows all ten spectral channels live while the device's Live switch is on.

The Plate Reader Assay and CAPTURE-Screen call the same fitting code (curve_fit.js), so the same readings give the same curve on either page. That is what makes the Cross-Validation comparison fair: any difference it finds comes from the instruments, not from two different pieces of arithmetic.

How the pieces connect

The frontend is a static site served by GitHub Pages; the backend is a FastAPI service on Render. They talk over HTTPS and WebSocket with no shared build step, so either half can be reused on its own. The plate reader tools never touch the backend at all: their arithmetic runs in the browser, and nothing is uploaded.

Why the device dials out

The backend runs in the cloud and cannot reach a device behind a lab or home router. So the direction is reversed: once CAPTURE-Screen powers on and joins Wi-Fi, it opens a secure WebSocket to /api/hardware/device and keeps it open, reconnecting by itself if it drops. Web pages only ever talk to the backend, which relays over that connection.

  • A measurement is one POST /api/hardware/read. The device runs one dark → light → dark cycle (about 3 s) and the backend hands the raw reading back. Dark subtraction, normalization and fitting all happen in the browser.
  • Live is one switch, owned by the device and shared by its button and every open landing page. It streams about two frames per second, pauses during a measurement, and switches itself off after 10 minutes, since leaving the LED on heats and bleaches the sample.

From a reading to a concentration

This section is the complete data model, step by step, as the code runs it. Every formula below is implemented in hardware_processing.js, curve_fit.js and hardware_local.js, and documented in the repository's docs/capture_screen_model.md.

  1. Raw counts, 10 channels
  2. Dark subtraction
  3. Normalization
  4. Signal F
  5. Weighted 4PL fit
  6. Inversion + 95% CI

The model has three layers. Signal processing turns raw counts into one number per tube, with its read noise and quality flags; it has no state and fits nothing. Calibration turns standards of known AHL concentration into a four-parameter logistic curve with its uncertainty, LOD, LOQ and usable range. Inversion turns a sample's signal into an AHL concentration with a 95% confidence interval, only inside the usable range. The last two layers are shared with the Plate Reader Assay.

1. One read

Every measurement is three consecutive frames. Each frame is all ten AS7341 channels (F1–F8, Clear, NIR) as integer ADC counts. The LED is on only during the light frame, which limits heating and photobleaching. The dark frames on either side measure everything that is not LED-excited fluorescence: ambient light, sensor offset, and drift.

2. Dark subtraction

For each channel k, with light frame L and dark frames D1, D2:

Sk = max(0, Lk − Dk), Dk = {{ frac('1', 'nd') }} ∑j=1nd Dj,k

The light frame sits between the two darks, so averaging them cancels any drift that is linear in time. The clamp at zero is there because a negative fluorescence has no physical meaning. If one dark frame is missing, the other is used; if both are, nothing is subtracted and the reading is flagged NO_DARK_PAIR.

3. Normalization to basic counts

Raw counts depend on the gain g and the integration time, so both are divided out:

Bk = {{ frac('Sk', 'g · tint') }}, tint [ms] = (ATIME + 1)(ASTEP + 1) × 2.78 × 10−3

With the default settings the divisor is 512 × 166.8 ≈ 85 400, so a real sample often reads well below one basic count. That is why the pages show fluorescence to four significant figures rather than a fixed number of decimals.

Normalization does not make readings under different settings interchangeable for calibration: the sensor is not perfectly linear in gain, and the LED current is not part of it. A curve therefore stays bound to the exact configuration it was made with (step 6).

4. Choosing the signal

F = BF4, scatter = BF3

F4 (~515 nm) is the channel closest to sfGFP's emission peak. F3 (~480 nm) sits near the excitation band, so it is mostly excitation light scattered by cells and debris: a turbidity proxy.

This is a placeholder. Proper linear unmixing needs an sfGFP emission spectrum measured on this instrument, and none has been measured yet. No basis values have been invented in the meantime, and every page that shows fluorescence says so. Each measurement, run and curve records its signal id (currently F4), so a curve can never silently convert a different kind of number once the definition changes.

5. Read noise of a single measurement

The two dark frames are two independent readings of the same background, so their difference estimates the noise of one frame:

σframe = max({{ frac('|D2 − D1|', '√2') }}, {{ frac('1', '√12') }})

The floor 1/√12 ≈ 0.29 counts is the standard deviation of ADC quantization, so the estimate is never zero. The fluorescence is L − D, so its variance is one frame's plus that of the dark mean:

σS = σframe √1 + 1/nd, σread = {{ frac('σS', 'g · tint') }}

This leaves out shot noise, which grows with the signal and cannot be estimated from a single read. Step 8 makes up for it with a noise model estimated from replicate tubes.

6. The configuration fingerprint

A curve is only valid for readings taken the same way. Every setting that changes what a reading means is condensed into six hex digits: 

canonical   = LED current (3 dp) | gain | atime | astep | build_id
fingerprint = first 6 hex digits of FNV-1a-32( UTF-8(canonical) )

The firmware build_id is changed deliberately whenever the reading path changes, so that every existing curve becomes stale on purpose. A measurement batch refuses a curve whose fingerprint or signal id does not match the instrument's.

7. Designing a calibration run

A run needs at least 4 distinct positive concentrations (a 4PL has four parameters), 1–10 replicates each, and 2–10 blanks (the LOD needs a blank SD). The tubes are read in replicate rounds: one blank, then every concentration from low to high. 

round 1: blank r1, 1 nM r1, 10 nM r1, 100 nM r1, 1 µM r1
round 2: blank r2, 1 nM r2, 10 nM r2, 100 nM r2, 1 µM r2
round 3:           1 nM r3, 10 nM r3, 100 nM r3, 1 µM r3

Interleaving spreads instrument drift over every concentration equally, instead of making all the high standards read late. Going low to high within a round limits carryover through the single cuvette. The software accepts only the next unread slot, so the order cannot be broken by accident.

8. The four-parameter logistic

The biosensor's response is sigmoidal on a log-concentration axis:

F(c) = B + {{ frac('T − B', '1 + (EC50 / c)h') }}, F(0) = B
4PL parameters
ParameterMeaning
B (bottom)Signal with no AHL, including leaky expression
T (top)Saturated signal at high AHL
EC50Concentration giving half the response, (T + B)/2
h (Hill)Steepness

Blanks enter the fit at c = 0, where the model equals B, so they pin the baseline directly. Internally the fit works on θ = (T, B, ln EC50, h): stepping in ln EC50 matches how the standards are spaced and keeps EC50 from ever going negative. The model is evaluated in a numerically stable form,

u = eh(ln EC50 − ln c), s = {{ frac('1', '1 + u') }}, F = B + (T − B) s

and one row of the Jacobian is

{{ frac('∂F', '∂T') }} = s, {{ frac('∂F', '∂B') }} = 1 − s, {{ frac('∂F', '∂ ln EC50') }} = −(T − B) s(1 − s) h, {{ frac('∂F', '∂h') }} = −(T − B) s(1 − s)(ln EC50 − ln c)

The code computes s(1 − s) rather than u/(1 + u)2 because it stays finite when u overflows. A curve is accepted only if T > B: a strain that does not respond gives no curve, rather than a line fitted through noise.

9. The noise model and the weights

Replicates are noisier at high signal than at low, so an unweighted fit would let the top standards dominate. The weights come from a two-component variance model:

Var(F) = a + b F2

a is additive noise (read noise, background), constant across concentrations; bF2 is proportional noise (pipetting, cell density, expression and, to first order, shot noise). Grouping the tubes by concentration and keeping groups with at least two tubes, a and b are fitted by ordinary least squares of each group's sample variance on its squared mean:

sg2 ≈ a + b Fg2

A variance cannot be negative: if b < 0 the code sets b = 0 and a = mean(sg2); if a < 0 it sets a = 0 and fits b through the origin. Each tube i then gets

σi = max(σread,i, √a + b yi2, 10−9 maxj|yj|), wi = 1/σi2

Taking the larger of the tube's own read noise and the replicate model matters, because the read noise leaves out shot noise: a tube with an unusually quiet dark pair would otherwise get a weight it does not deserve. The last term only prevents division by zero.

With one tube per concentration and no read-noise estimate (typed-in data), there is no noise information at all. The fit is then unweighted (σi = 1), and the reading variance used later is taken from the residuals: a = RSS/(N − 4), b = 0.

10. Fitting: weighted Levenberg–Marquardt

The fit minimizes, over the N included tubes,

χ2(θ) = ∑i=1N ({{ frac('yi − F(ci; θ)', 'σi') }})2

Starting values: B0 is the blanks' mean, T0 the highest group's mean (nudged above B0 if needed), EC50,0 the standard whose mean is closest to (T0 + B0)/2, and h0 = 1. Each iteration solves the damped normal equations for a step δ:

(J⊤WJ + λ diag(J⊤WJ)) δ = J⊤Wr

with W = diag(wi) and ri = yi − F(ci). A step that lowers χ2 is accepted and λ divided by 10, towards Gauss–Newton; otherwise λ is multiplied by 10, towards gradient descent, and the step retried. Steps that would put h outside (0.05, 20) are rejected. The fit stops when the relative improvement falls below 10−10, when no step can be accepted, or after 500 iterations. At the optimum, the parameter covariance is

Σθ = (J⊤WJ)−1 · {{ frac('χ2min', 'N − 4') }}

Scaling by the reduced χ2 corrects for a noise model whose absolute scale may be off. If the matrix is singular, or any entry is not finite, the fit is reported as not converged and no curve is made. An excluded tube stays in the run, on the plot and in the CSV, and is recorded on the saved curve with a mandatory reason.

11. LOD, LOQ and the usable range

The limits follow the blank-based definition: the blank level plus 3 (LOD) or 10 (LOQ) blank standard deviations.

yblank = max(mean of blanks, B), FLOD = yblank + 3sblank, FLOQ = yblank + 10sblank

The blank level is never allowed below B, since the curve cannot invert a signal below its own bottom. If FLOQ ≥ T, the blank scatter is too large relative to the response and no curve is made. Each limit is converted to a concentration through the inverse 4PL:

LODnM = EC50 ({{ frac('FLOD − B', 'T − FLOD') }})1/h

and the curve returns a number only inside

cmin = max(LODnM, lowest standard), cmax = min(highest standard, EC50 · 191/h)

Below the LOD a signal cannot be told apart from the blank; below the lowest standard or above the highest, the curve would be extrapolated. At EC50 · 191/h the curve has reached 95% of its span (19 = 0.95/0.05). Beyond it the curve is so flat that a tiny change in F maps to a huge change in c, and the inversion error blows up. If cmin ≥ cmax, there is no usable range and no curve.

12. Inversion with a 95% confidence interval

Solving the 4PL for c:

ln c = ln EC50 + {{ frac('1', 'h') }} ln {{ frac('F − B', 'T − F') }}

ConditionStatusReported
F ≤ B, or c < cminbelow_lodno number
F ≥ T, or c > cmaxabove_rangeno number
otherwiseokc with its 95% CI

The uncertainty is propagated on ln c rather than on c, because concentration errors are multiplicative. Two independent sources contribute: the reading, through the noise model; and the curve, through Σθ. The gradients of ln c are

gF = {{ frac('∂ ln c', '∂F') }} = {{ frac('1', 'h') }}({{ frac('1', 'F − B') }} + {{ frac('1', 'T − F') }})
gθ = (−{{ frac('1', 'h(T − F)') }}, −{{ frac('1', 'h(F − B)') }}, 1, −{{ frac('1', 'h2') }} ln {{ frac('F − B', 'T − F') }})

and the delta method combines them, with n the number of tubes averaged into F:

Var(ln c) ≈ gF2 {{ frac('a + bF2', 'n') }} + gθ⊤ Σθ gθ
CI95 = [ eln c − 1.96√Var, eln c + 1.96√Var ]

The interval is asymmetric in nM, which is correct for a quantity measured on a log scale. gF grows without bound as F approaches B or T: that is the formal reason the CI widens sharply at both ends of the curve, and part of why the usable range stops at 95% of the span.

13. Replicates: average first, then convert

A sample is converted once, from the mean of its counted tubes, not by averaging per-tube concentrations:

F = {{ frac('1', 'n') }} ∑i=1n Fi, estimate = invert(F, n)

The 4PL is non-linear, so the mean of converted values is biased, and one tube near the flat top would dominate it. Averaging in signal space also splits the variance correctly: the reading variance is divided by n because the tubes are independent, but the curve covariance is not, because every tube goes through the same fitted curve. More replicates therefore narrow the CI only down to the curve's own uncertainty, never below it.

A batch's own blanks are a check, not a subtraction: the curve already contains its baseline B. If the batch blank converts to anything other than below_lod, the Measure page warns that the blank differs from the calibration blanks or the instrument has drifted.

14. The plate reader and cross-validation

The Plate Reader Assay feeds plate-reader readings into the same fit and inversion (steps 8–12). Its readings carry no read-noise SD, and its curve serves only the readings entered with it, since a plate reader's scale changes with instrument, gain and day. With OD normalization, each well's signal is

signal = {{ frac('F − Fmedium', 'OD600 − ODmedium') }}

using the means of a medium-only blank. Cross-Validation then pairs the two instruments' results by sample name. Only pairs with a number on both sides are compared, since a bound says where a value is not, not where it is. Agreement is measured on the log scale, because inferred concentrations span decades and their errors are proportional. With di = log10(cCAPTURE,i / cplate,i):

GMR = 10d, LoA95 = [ 10d − 1.96sd, 10d + 1.96sd ]

alongside the number of pairs whose 95% CIs overlap. No pass/fail threshold is set: there will be none until real data says what agreement to expect.

Use it, run it, extend it

To use LasReader you need only a browser: open the live app. To run it locally, you need Python 3.14 and Git; the frontend has no dependencies and needs no Node.js. 

git clone https://gitlab.igem.org/2026/software/ncku-tainan/lasreader.git
cd lasreader
bash scripts/setup.sh      # once
bash scripts/dev.sh        # backend on :8000, frontend on :5500

On Windows PowerShell, run scripts\setup.ps1 and scripts\dev.ps1 instead. Interactive API documentation is at /docs once the backend runs, and cd backend; pytest runs the test suite.

Reproducing a result without the instrument

On the Calibrate page, choose Enter recorded data and type in previously recorded readings with the instrument configuration they were read under. Fitting, LOD/LOQ and saving work exactly as for a device run, so a published curve can be refitted from its recorded values. A plate reader assay's CSV holds every reading, so its curve can be refitted from the file.

Extending it

  • A backend feature is a folder under backend/app/ with its own router.py, wired in with one include_router() line and tested under backend/tests/.
  • A frontend page is one .html file that loads js/config.js first, then its own script. GitHub Actions deploys the whole folder as-is.
  • A change to the model updates the matching section of docs/capture_screen_model.md in the same change.

The storage layer is isolated behind one file, hardware_api.js, so moving runs and curves from the browser to a database changes only that file. LasReader is released under the MIT License: future teams may use, modify and redistribute it, keeping the copyright notice.
