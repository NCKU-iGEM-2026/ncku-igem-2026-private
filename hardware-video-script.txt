--------------------------------------------------------------------------------
轉場：先讀這段
--------------------------------------------------------------------------------

11 個剪接點全部是 **14 格（0.47 秒）的交叉淡入淡出**，不是硬切。

轉場會重疊兩個鏡頭。為了不讓時間軸整個往前位移，**每個鏡頭多渲染 0.47 秒**
（最後一鏡除外），多出來那段正好被下一鏡的淡入蓋住。結果是：

    鏡頭的絕對起點 = 各 dur 的累加
    全片長度      = 各 dur 的總和 = 203.00 秒
    字幕          = 不受轉場影響

所以下面每個鏡頭寫的「可見長度」之後，實際上還會再演 0.47 秒的尾巴。

**每個鏡頭左上角的說明區塊都在 0.55–1.45 秒之間淡入。**
那是刻意排在轉場（0–0.47 秒）結束之後，否則文字會疊在前一個鏡頭上。
語速放慢時這組數字**沒有**跟著拉長，因為它對的是轉場，不是鏡頭長度。

工具鏈
================================================================================

專案在 C:\Users\user\capture-screen-video（刻意放在 wiki repo 外面，
不要把 node_modules 或 out/ 丟進 ncku-tainan repo，會拖垮 GitLab CI）。

  npm run studio          Remotion Studio，拉時間軸即時看
  npx remotion render src/index.jsx Film out/capture-screen-av.mp4 --codec=h264
                          出成品（畫面 + 字幕 + 音樂）

  python tools/audit.py           六段總檢查
  python tools/check_film.py      字幕時間、重疊、閱讀速度、覆蓋率
  python tools/make_captions.py   重產字幕（改過旁白稿或鏡頭長度之後要跑）
  python tools/measure_vo.py      重量配音長度（換過音檔之後要跑）
  python tools/make_music.py      重產音樂
  python tools/make_sfx.py        重產音效
  tools/tts.ps1 -Rate 1           產暫用配音（目前語速）

要加真人旁白，四步：
  1. 錄好，覆蓋 public/vo/01.wav … 12.wav（檔名不要改）
  2. python tools/measure_vo.py
  3. python tools/make_captions.py
  4. src/Soundtrack.jsx 的 USE_VOICEOVER 改成 true
真人錄音的長度一定跟現在的機器配音不同，所以第 2 步之後要回頭看
shots.json 的鏡頭長度夠不夠，不夠就加長再跑一次 make_captions.py。

**不要刪 public/vo/*.wav。** 即使旁白關閉，那些檔案是字幕時間的唯一依據。
